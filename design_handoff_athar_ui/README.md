# حزمة التسليم — واجهات نظام أثر (Athar ERP)

## ما هذه الحزمة
٢١ شاشة واجهة (Wireframes عالية التفصيل) لنظام أثر، مبنية على المحتوى الفعلي للمستودع
`Amina-Mansouri/AtharERP_System` (الوحدات ٠١ الصلاحيات والمصادقة، ٠٢ إدارة المشاريع،
٠٣ إدارة المواقع والعمليات الميدانية) + مجموعة «عام» للإشعارات.

**الملفات المرفقة مراجع تصميم مكتوبة بـ HTML — ليست كوداً للنسخ.**
المطلوب من المطوّر: إعادة بناء هذه الشاشات داخل بيئة المستودع نفسها
(ASP.NET Core MVC 8 + Razor Views + Bootstrap 5 + jQuery، RTL عربي) باستخدام أنماطه القائمة.

## درجة الدقة
**متوسطة-عالية (mid-fi)**: التخطيط والأعمدة والحالات والنصوص نهائية ومقصودة —
انسخها كما هي. الألوان والخطوط والمقاسات المذكورة في `SCREENS.md` هي القيم الفعلية
المستخدمة في المراجع؛ استخدمها إن لم يكن للمستودع نظام تصميم أقوى منها.
المستطيلات المشطّبة (hatched) = أماكن صور/مستندات حقيقية، والمربعات الفارغة = أيقونات Lucide.

## حقائق أساسية عن المستودع (مؤكدة من الكود)
- **الكيانات كاملة (٥٧ كياناً)**: `Project`, `ProjectStage`, `ProjectStep`, `ProjectTask`,
  `TaskAssignee`, `TaskTodo`, `TaskDependency`, `ProjectCost(+Subtask)`, `ProjectTimeline`,
  `Site`, `SiteOperation`, `SiteDailyReport(+Photo)`, `SiteQualityCheck`, `SiteSafetyCheck`,
  `SiteContractor`, `SiteMaintenance`, `SiteDocument`, `SiteSupplyRequest`,
  `ApplicationUser`, `EmployeePosition`, `Department`, `Permission`, `RolePermission`,
  `UserPermission`, `Notification`, `AuditLog`, `FinancialRecord`.
  **لا تُنشئ كيانات جديدة إلا المذكورة صريحاً في `BACKEND.md`.**
- **الـ Controllers موجودة (١٨) والـ Views موجودة ومختبَرة محلياً** عبر الوحدات ٠١/٠٢/٠٣.
  ⚠️ **تنبيه**: ملفات `Views/**/*.cshtml` **غير مرفوعة إلى GitHub** (المتتبَّع فقط
  `Views/Shared/_Layout.cshtml.css`) — لذلك أي قراءة للمستودع عن بُعد تبدو كأن الـ Views غير موجودة.
  **المصدر الصحيح هو نسختك المحلية.** المطلوب **إعادة تصميم واجهات تعمل فعلاً**،
  لا إنشاء من الصفر: حافظ على منطق الصلاحيات والروابط في `_Layout.cshtml` الحالي
  ولا تستبدله بسقالة فارغة.
  (يُنصح برفع الـ Views إلى المستودع حتى تُقرأ صحيحة في المرات القادمة.)
- **جاهز في الـ Services**: `ProjectCalculationService` (الأوزان والنِسَب وأيام التأخير)،
  `PermissionService`، `NotificationService`، `AuditService`، `FileUploadService`، `GeoHelper`.
- العملة: الدينار الليبي (د.ل) · الأكواد: `PRJ-YYYY-NNN` · كل الصفحات RTL عربية.

## خطوات العمل المقترحة (بالترتيب)
1. **الأساس**: تعديل `_Layout.cshtml` القائم (لا استبداله): استبدال الـ Navbar الحالي
   بشريط علوي + قائمة جانبية، مع **الحفاظ على كل منطق الصلاحيات والروابط الموجود**،
   + طبقة توكنز في `wwwroot/css/site.css`. مرجع القياسات: `SCREENS.md §0`.
2. **الشراكات المشتركة (Partials)**: ترويسة الصفحة، شريط الأرقام، شريط التصفية، الجدول،
   الشارات (tags)، أشرطة التقدّم، لوحة التفاصيل الجانبية، الترقيم. كل شاشة بعدها تصبح تركيباً.
3. **الوحدة ٠١**: أعد تصميم الـ Views القائمة: تسجيل الدخول → لوحة المعلومات → المستخدمون →
   ملف المستخدم → الأدوار والصلاحيات → الأقسام.
4. **الإشعارات** (عام): شاشة القائمة + قائمة الجرس المنسدلة + عدّاد غير المقروء.
5. **الوحدة ٠٢**: العملاء → المشاريع → تفاصيل المشروع → المهام → التكاليف → الجدول الزمني.
6. **الوحدة ٠٣**: المواقع → تفاصيل الموقع → التقارير اليومية → الفحوصات → المقاولون →
   الصيانة → طلبات التوريد.
7. **الشاشات الشاملة الناقصة**: بعض بنود القائمة (المهام، التكاليف، الجدول الزمني،
   وقوائم الوحدة ٠٣ الشاملة: التقارير اليومية، الفحوصات، المقاولون، الصيانة، طلبات التوريد)
   هي **قوائم عبر كل المشاريع/المواقع**، والموجود حالياً نُسخ مرتبطة بمشروع/موقع محدَّد.
   ابنها في مرحلتيها (٤ و٥)، ومؤقتاً اربط البند بأقرب صفحة فعلية مع `// TODO` واضح.
8. **تعديلات المنطق والبيانات** في `BACKEND.md` — نفّذها عند الشاشة التي تحتاجها،
   لا كلها مقدماً.

## معيار «لم نفقد أي تفصيلة»
لكل شاشة، تحقّق من: الترويسة (الوحدة + العنوان + الأزرار) · شريط الأرقام بنفس البنود
والترتيب · التبويبات بنفس الأسماء والعدّادات · شريط التصفية بنفس المرشّحات ·
أعمدة الجدول بنفس الترتيب والعرض النسبي · الشارات وقيمها · لوحة التفاصيل الجانبية ·
سطر الترقيم والملاحظة السفلية. القائمة الكاملة في نهاية `SCREENS.md`.
